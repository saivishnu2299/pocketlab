# Troubleshooting

Run commands from the PocketLAB repository folder on your computer. Start with `./pocketlab doctor` for local prerequisites/runtime, `./pocketlab doctor --sd CARD` for an installed card in a reader, or `./pocketlab doctor --usb` after opening PocketLAB on the connected Brick. Replace `CARD` with your actual mounted card path. Diagnostics return a nonzero exit status on failure; add `--json` for machine-readable output.

- **Python missing or too old:** check `python3 --version` in the same terminal. Card setup needs 3.9+ (macOS: `xcode-select --install`); building mini apps needs 3.12+. See the [prerequisite instructions](INSTALL.md#computer-prerequisites), then ensure `python3` selects that installation.
- **"Operation not permitted" on macOS, or `cards` shows `unreadable`:** macOS privacy settings block the terminal or agent app from reading removable volumes. Allow that app in System Settings → Privacy & Security → Files & Folders (Removable Volumes), or in Full Disk Access, then retry. The card is not damaged.
- **Setup menu cannot run in the agent's terminal:** `./pocketlab setup` needs an interactive terminal. Use explicit flags from the [installation guide](INSTALL.md), such as `setup --sd CARD` or `install --usb --confirm-model TG4040`, after selecting the correct setup path.
- **Card missing from `cards` or the setup list:** check that it appears in your file manager, then pass its mounted volume root explicitly with `setup --sd CARD` (or choose **m** in the menu). A working stock card has `Apps` and `Roms` directories. For a blank FAT32 card, use `./pocketlab prepare-card --sd CARD --new-card`.
- **Card was formatted but has no apps:** the explicit `format-card` command only formats it. Run `prepare-card --sd CARD --new-card` to install the stock SD base and PocketLAB, then `doctor --sd CARD`. Do not run new-card preparation on a card containing files you want to keep.
- **Stock copy interrupted:** keep the hidden `.pocketlab-preparing` folder. Reconnect the same card and run `./pocketlab setup --sd CARD` or repeat the original `prepare-card` command. For a partial copy from before this installer, use `./pocketlab prepare-card --sd CARD --resume`. If setup finds a conflict, it identifies the path and preserves the existing file.
- **No ADB device:** use a data-capable cable in the bottom port, wake the Brick, close USB Storage, and inspect `adb devices`. With multiple devices supply --serial. On Linux check the host's USB permissions.
- **PocketLAB not installed:** this is expected from `doctor --usb` before the first installation. Use the complete bundled runtime with `./pocketlab setup --sd CARD`, or `./pocketlab install --usb --confirm-model TG4040` on a prepared stock card. Open Apps → PocketLAB afterward and repeat diagnostics.
- **Controller not running:** open Apps → PocketLAB. USB installation can create the launcher entry; the user opens it the first time.
- **Setup finished but eject failed:** eject the card in your file manager. Setup has already verified the copied files.
- **Build failure:** the previous binary/installed app is retained. Fix source and retry. setup --sdk explicitly prepares the compiler cache. A checksum failure requires inspecting/removing only the named cached download, never formatting a card.
- **App misses readiness:** call pocketlab_ready() after the first usable frame and declare ready=file. Startup rollback restores the previous code package; data migration and later application logic are the app author's responsibility.
- **Lost USB acknowledgement:** inspect status/logs before retrying; the operation may have completed.
- **Shell update waiting for its first launch:** eject the card, insert it into the Brick, and open PocketLAB. The launcher checks startup and restores the prior runtime if startup fails.
- **Interrupted shell update:** the pending record is `data/pending-shell-update`. With the card in a reader, use `./pocketlab recover --sd CARD`. With USB connected to the Brick, use `./pocketlab recover --usb`. Both use the recorded runtime backup. Very old launchers may need the explicit recovery command after an interruption.
- **Restore a previous version:** `./pocketlab backups --sd CARD` lists available backups. Choose a token or an older `.PocketLab.backup-*` name and run `./pocketlab recover --sd CARD --backup NAME`. Recovery preserves the current apps and saves.
- **Disk getting full:** new card setup needs room for the remaining stock files. Runtime updates need room for the changed files and a small rollback copy. `./pocketlab backups --sd CARD` lists retained backups. After testing the current app, `--prune --keep 2` can remove older backups while protecting pending recovery.
- **Visible USB board without a serial port:** stock drivers or USB mode may not expose a serial interface. Passive bridge discovery is not an ESP32 identity or firmware protocol guarantee.

Logs are in Apps/PocketLab/data/pocketlab.log (previous run: pocketlab.previous.log). Remove device identifiers, personal paths, and app data before attaching logs to an issue. Never upload an entire card or development cache.

Only one PocketLAB setup process can use the selected card at a time. If setup reports another process, let that process finish or close it before retrying. For a stuck USB installer lock on the Brick, check status and recovery first. Rebooting the Brick clears its temporary lock.
